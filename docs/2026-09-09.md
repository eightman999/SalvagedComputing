# 2026-09-09 — Project Inception Log

## Summary

今日の中心的な発見は、古いGPUを「新しいGPUの劣化版」として一列に並べるより、**容量・帯域・precision・runtime・PCIe・消費電力ごとに別の役割を持つ異種計算器官として扱う**方が有用ではないか、ということだった。

この考えを独立プロジェクトとして切り出し、名称を **SalvagedComputing** に決定した。

日本語での作業名は「限界カスGPU鯖計画」。

## 1. P100の再評価

Tesla P100 16GB は「古いから使えないGPU」ではなく、実際の学習workloadを担当できる資産として再評価した。

今日のnovllm系作業でもP100を学習laneとして継続利用し、J72/J96等の実験候補へ投入した。

既存のRTX 3060 + P100異種構成でも、4096-token trainingを完走した実績があり、過去の実測では約106.3 s/step・308 tok/sの構成が得られている。この実績は、旧GPUを仕様表だけで捨てず役割分担する方針の根拠になる。

ただし、この3060+P100機は `llm_master_now` であり、SalvagedComputingの主対象である貫井のGPU牧場とは区別する。

## 2. Nukui Extreme Nodeを主対象として定義

今日、限界GPU鯖という語が指す対象を明確化した。

**Nukui Extreme Node:**

- BIOSTAR TB250-BTC PRO
- Intel Celeron G3930
- PCIe 3.0 x16 ×1 + x1 ×11
- RX 5500 XT / RX 6400 / GTX 550 Ti / GT 710 / 730等を含む異種GPU pool

主戦略:

- 1つの巨大モデルへ全部を束ねない
- GPUごとに独立roleを割り当てる
- PCIe x1を欠点として隠さず、帯域制約込みで測る
- weak CPUによるpreprocessing bottleneckは別ノードへ逃がす

## 3. 24GB旧GPUの役割分担

### P40 24GB

実用寄りの24GB候補。量子化推論 / model residencyを中心に評価する。

今日話題になった販売候補: 約 **¥39,000**。

### M40 24GB

「安価な大容量slow node」としてなら意味がある。

判断:

- P100の学習性能を置き換えるカードではない
- J128/J160のような容量が先に効く探索では価値がある可能性
- 24GBが本当に安い時だけ候補
- 本格trainingならx16直結 + 強制風冷を優先

### Quadro系

RTX 4000 / M4000表記の約 **¥47,000**候補も比較対象に上がったが、ブランド名ではなくVRAM・世代・runtime・価格で判断することにした。

## 4. Architecture follows hardware

今日読んだ記事群から、SalvagedComputingの研究方針として以下を採用した。

- GEMM shape / SM / tileに合わせてmodel dimension自体を調整する余地がある
- quantizationは単なるVRAM削減ではなく、kernel availability・outlier・conversion overheadまで含めて実測する
- full self-attentionを唯一の正解にしない
- recurrent / sparse / retention / low-bit / logic-gate系など、弱いhardwareに合うarchitectureを探す

4GB級GPUにdense Transformerを載せて失敗しただけで `UNUSABLE` としない。

## 5. Extreme Hardware Organ hypothesis

今日の仮説を名前付きで残す。

**Extreme Hardware Organ hypothesis:**

> 異種・旧世代GPUの集合を、巨大な仮想GPUとして均質化するのではなく、それぞれ異なる役割を持つ計算器官として構成した方が、限界hardware全体の実用価値を引き出せるのではないか。

例:

- P100 = dense training organ
- P40 = quantized inference / memory organ
- M40 = slow large-memory organ
- tiny legacy GPU = specialist / odd-architecture organ
- CPU / other host = preprocessing organ
- storage = artifact/model store
- network = transport

これは現時点では仮説。実測で否定されることも許容する。

## 7. Agent / remote experiment lesson

今日参加したイベントでは、スマホ上のplannerから自宅計算機へ指示し、実験結果ZIPを再びplannerへ戻す運用を共有した。

実用上、人間のZIP/copy-paste bridgeがボトルネックになっていることを確認。

SalvagedComputingでも将来は以下を目標とする。

```text
planner
  -> experiment contract
Nukui executor
  -> run
  -> machine-readable result + artifact
reviewer
  -> accept / reject / next experiment
```

ただし、遠隔自動化のためにhost全権限を与えることはしない。GPU job、workspace、artifact write等をcapability単位で分離する。
